kula 0.3.0

git, with a map.

Kula turns a repository into a knowledge graph and puts it to work, for you and for your agents.

Every git command. A graph of your code. Architectural review. Issues, proposals and notes stored in git. Agent workflows, fences and memory anchored to the code. One binary, no server, no account, no telemetry.

11languages parsed
21MCP tools
1.4 sto index git itself
0servers or accounts
A live map

Every function, class and file, with calls, imports and clusters. Current with every commit.

Fences that know code

Lock a symbol, hide secrets, scope a task. Enforced on every edit, shell command and commit.

Teams of agents

Each agent in its own workflow, in one checkout, teams answering to teams.

Memory that goes stale

Facts pinned to the code they describe, marked stale the moment it changes.

Structural review

What a branch does to the architecture: symbols, edges, blast radius, risk.

A graph you can take

The whole graph as RDF. Export it, or ask it anything in SPARQL.

Quick start

cd your-repo
kula init                          # git init if needed · kula.toml · hooks · agents · first graph
kula view                          # the map at http://localhost:7420
kula impact parseConfig            # what breaks if this changes
kula graph-diff main WORKTREE      # what uncommitted work does to the architecture
kula task start "split auth" -w refactor   # agents may restructure; tests are locked
kula commit -am "ship it"          # and it is still just git

Start

kula init

Runs once per repository, safe to run again. Interactive, or -y for every default.

kula init -y --hooks --agents --ci github
stepwhat it does
gitgit init when the folder is not a repository yet
kula.tomlthe project's shared settings. Commit it so the team shares one graph
.kula/the graph database. Ignores itself; your .gitignore is never touched
--hooksreindex after commit, checkout and merge, plus the pre-commit fence check. Existing hooks are kept
--agentsMCP and the pre-edit hook for Claude Code, Cursor, Codex and Gemini CLI; the brief in AGENTS.md
--ci.github/workflows/kula.yml or .kula-ci.yml with the check gate
graphthe first index (skip with --no-index)

Start

kula.toml

Every key is optional. A repository without the file behaves exactly as plain git.

[project]
name = "shop"
default_branch = "main"          # what proposals and kula check compare against

[index]
exclude = ["**/generated/**"]    # on top of .gitignore
max_file_kb = 1024

[check]
max_risk = "medium"              # none · low · medium · high

[agents]
hide_secrets = true              # .env, keys, certificates never reach an agent
memory = true
docs = ["docs/ARCHITECTURE.md"]  # every agent reads these first

[[guard]]
symbols = ["src/billing.rs:charge_card"]
level = "locked"
reason = "money moves here; a person changes it"

[[workflow]]
name = "db-migrate"
scope = ["migrations/**"]
memory = "read"

[[team]]
name = "ship"
under = "steer"
members = [
  { agent = "claude", workflow = "fix", role = "lead" },
  { agent = "cursor", workflow = "tests", reports_to = "claude", hands_off = ["codex"] },
]

The map

Explore the graph

Tree-sitter parses TypeScript, JavaScript, Python, Rust, Go, Java, C, C++, C#, Ruby and PHP. Calls resolve through imports; clusters come from label propagation. Every graph command takes --json.

kula query auth                  # search symbols and files
kula context login               # callers, callees, container, source
kula impact login [--down]       # blast radius, graded by risk
kula trace main charge_card      # shortest call path
kula flows · kula clusters       # execution flows, functional clusters
kula deps --undeclared           # imported but in no manifest

Each directory settles into its own territory; the most connected symbols become tiles. ⇧-click lights the shortest path, f shows fences.

The map

Review changes

Review the structure, not only the lines. Any two branches, tags, commits or the working tree, built from git objects without a checkout.

kula graph-diff main WORKTREE     # symbols gained, lost, rewritten; edges added and cut
kula compare main feat/auth        # graph-aware branch comparison
kula lg                            # commit graph

Contrast. Overlay, side by side or report; changed symbols marked + − ~.

Impact. The blast radius, shaded by depth, graded by risk.

The map

Still just git

Kula is a superset of git. Anything it does not know goes straight to git, so hooks, signing, credential helpers and LFS keep working.

kula commit -am fix · kula rebase -i main · kula bisect start · kula lfs pull
kula git <args>                  # explicit pass-through
kula -C ../other status            # like git -C

The map

Issues, proposals, notes

Stored as git objects on refs/kula/meta. Full history, nothing touches your branches, and they work offline and sync through any remote.

kula issue new "Recall ignores recency" -a src/memory.rs:recall -l memory
kula pr new "Cache renames" --base main --head feat/cache
kula pr show 1 · kula pr merge 1   # with its graph impact
kula note add symbol:Guards "One verdict per path."
kula sync                         # push and pull refs/kula/meta

Proposals. Thread, graph impact, merge.

Notes. A knowledge graph beside the list; [[ links a symbol.

The map

RDF and SPARQL

Symbols, files, clusters, calls, imports, notes, memories, issues and fences under kula: with stable urn:kula: IRIs. Oxigraph answers SPARQL 1.1, read only. Hidden code is never in the graph.

kula kg export -f jsonld -o graph.jsonld     # ttl · nt · jsonld · rdfxml
kula kg sparql 'SELECT ?name (COUNT(?c) AS ?callers) WHERE {
  ?s a kula:Function ; kula:name ?name . ?c kula:calls ?s
} GROUP BY ?name ORDER BY DESC(?callers) LIMIT 10'

Workflows

A workflow is a work mode. Start a task in one and its fences, scope, steps, docs and memory policy apply to every agent until it is done.

kula workflow list
kula task start "split the auth module" -w refactor
kula workflow install refactor   # Claude Code subagent, Cursor rule, Gemini command
kula workflow prompt refactor    # for any system prompt

Fences

Fence a path or a symbol, which follows the code when it moves. The strongest level wins, so a task can narrow what kula.toml allows, never widen it.

hidden>locked>scope>review>open
levelmeaning
hiddennever read or edited, left out of every agent answer. Likely secrets are hidden by default
lockedread, never edited
scopeoutside the active task's scope
revieweditable; kula check flags it for a person
kula guard list · kula guard check src/billing.rs
kula agents suggestions · kula agents accept 1   # agents suggest; a person decides

How fences hold

Fences are not a paragraph in a prompt. Every way an agent can change code meets the same verdict.

kula.tomltasksecrets→one verdict→MCPpre-tool hookpre-commitkula runverify_editCIUI
how an agent actswhat holds it
a file toolthe pre-tool hook refuses the call and says why
a shell commandrm, mv, sed -i, > file, tee, git rm and inline scripts (python -c, node -e) are read for every path they write
switching kula offediting kula.toml or a hook, kula task done, git commit --no-verify, core.hooksPath: refused, always
a committhe pre-commit hook refuses an agent's commit holding fenced changes
an unknown harnesskula run makes fenced files read-only for the run, puts back anything fenced it changed, and keeps the agent's version in .kula/run/
a branchkula check fails it in CI
# what an agent sees
kula guard: crypto.py is locked for agents – crypto is reviewed by hand (kula.toml guard #1).
Leave it to a person, or suggest a change to the fence with the `suggest` tool.

Agents

Any harness, any model

Wrap any agent CLI. It runs in a workflow and a task, held to the fences for the whole run. Exit code 3 means something fenced was put back.

kula run -w fix --agent aider -- aider
kula run -w docs --agent opencode -- opencode run -m openrouter/deepseek/deepseek-v3.2 "document calc.py"
kula run -w tests --agent minimax -- mcode exec --model <provider/model> "cover the parser"
# tested: opencode + DeepSeek V3.2 on OpenRouter, docs workflow
✓ README.md written and committed
⊘ put back calc.py  task covers only **/*.md, docs/**, …
  the agent's versions are in .kula/run/1791290556

Agents

Teams

A team gives every agent its own workflow, and the hook holds each to its own, at the same time in one checkout. Teams carry a lead, who answers to whom, hand-offs and prompts. A team can answer to another team, so they nest into a society.

kula team save ship -m claude=fix:lead -m cursor=tests -m codex=explore:review
kula team prompt ship cursor     # its full instructions: team, role, place, workflow
kula team start ship · kula team stop · kula team list

Agents › Teams draws the society on the same renderer as the code map: a territory per team, hub tiles for leads, flow along hand-offs. Toggle it off for nested boxes.

Agents

Autoresearch

Give an agent a number to move and the code it may change. Kula runs the metric itself, commits what improves it and reverts what does not. Agents never report their own scores.

kula research init --metric "cargo bench 2>&1 | grep -o '[0-9.]* ms' | tail -1" --goal min --scope "src/index/**" --budget 40
kula research start                     # baseline, on a research/ branch
kula research try "cache the parser"      # measured: kept as a commit, or reverted
kula research status                    # baseline, best, every experiment
hypothesis→edit in scope→kula measures→better: commit·worse: revert→remember why

Agents

Memory

One fact pinned to a symbol, a file or the repo, stored in git. Recall ranks by the graph: the target, its file, its callers and callees. When the code changes, the memory comes back stale instead of being trusted.

kula memory add login "tokens are hashed twice for legacy clients"
kula memory recall login
kula memory stale 4 · kula memory confirm 4 · kula memory rm 4
remember→fresh→ code changes →stale→ confirm →fresh

Ship

CI gate

Compares HEAD with a base through the graph: files, symbols touched, dependents, clusters crossed, undeclared imports. Exits 2 when risk exceeds max_risk or a change touches locked or hidden code.

kula check                            # base and gate from kula.toml
kula check --base origin/main --md     # markdown for the PR summary

How it works

any revisionbuilt from git ls-tree and one cat-file --batch, cached per commit, no checkout
storage.kula/graph.db, built beside the live file and swapped in with one rename
metadataissues, proposals, notes, memories on refs/kula/meta
gitnever reimplemented; kula shells out to git
