# Edge and schema audit – 2026-11-12 (P1.1.10)

kula-critic audited the resolvers, the confidence tiers and schema 4 against the code and the bench. Every finding was fixed or accepted below; none is left open as a blocker.

## Bench after the fixes

`KULA_NO_AGENT=1 python3 bench/edges/score.py --kula target/debug/kula`: precision 0.97, recall 1.00 (tp 73, fp 2, fn 0). `resolved` 59/59, `inferred` 11/12, `guessed` 3/4. The truth set now holds path qualified pairs, so an edge to the wrong same-name symbol counts as wrong.

## Fixed

- Bench scored by bare name, so a wrong same-name target counted as a hit. Truth is now `path:name` pairs; new fixtures cover each case below.
- TS and Go resolver gaps found by the path qualified truth (wrong same-name targets) were closed in `ts.rs` and `go.rs`.
- IMPORTS edges were all `resolved`. A suffix lookup is now `inferred` when one file matches a multi-segment key, `guessed` otherwise. Go imports go through the `go.mod` module path; with no `go.mod` the fallback is `guessed`.
- Python absolute imports fell back to any file with the same suffix (`import requests` hit `vendor/x/requests.py`). The fallback now only accepts a single source root.
- Rust `let x = T::f(); x.m()` assumed every associated fn returns `T`. `f` must now be `new`, `default`, `new_*` or return `Self`/`T`, checked in the type's own file even when it lives elsewhere.
- Rust 2015-style `use` paths without `crate::` missed modules declared in the crate root. The first segment now falls back to the root when `lib.rs`/`main.rs` declares `mod seg;`.
- A bare name with several matches silently picked one. `resolve_one` now fails with `ambiguous: N matches` and lists `path:name`, or `path:Owner.name` when only the owner tells them apart. `path:Owner.name` and `path:Owner::name` are accepted inputs. A miss suggests close names.
- Old indexes kept wrong edges until a manual rebuild. Schema is now 5 and the index records the kula version that built it; an outdated index prints one stderr line asking for `kula index` (`KULA_QUIET_STALE` silences it).
- `trace`/`impact` BFS kept the first tier it saw for a node. A surer edge at the same depth now upgrades the hit, its `via` and the path tier.
- USES_TABLE edges were `resolved` though they come from string matching; they are `inferred`. File level DEPENDS and package IMPORTS rows now carry the best edge tier, and `context` reports a tier per neighbour.
- MCP `min_confidence` accepted any string. Unknown values are an error.
- `docs/design/resolution.md` is updated with the bench command, counts, IMPORTS tiers, schema 5 and the ambiguity rule.

## Accepted

- `lib.rs:pick_glob -> m2.rs:dup_fn` (`guessed`): two glob imports export the same name; kula cannot pick without type info, and the tier says so.
- `wheel.go:Shadow -> wheel.go:Spin` (`inferred`): interface satisfaction by method name, by design never `resolved`.
- Fences and `pre_edit` still count every tier (safe side); only the `verify_edit` dangling-caller check skips `guessed`.
